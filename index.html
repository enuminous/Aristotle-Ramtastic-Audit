01 / What you are looking at

One project.
Several layers of evidence.

This repository brings the source, audit, and reproducible checks together. Each layer answers a different question.

Lean checks that a conclusion follows from its definitions and hypotheses. That is a powerful guarantee. An audit then asks whether those definitions and hypotheses represent the intended mathematical problem.

A structure can contain a difficult theorem as an input field. A later theorem may correctly use that field, while the difficult construction remains to be supplied. Finding that gap is part of the work.

What this package establishes: reproducible proofs of the written propositions, explicit rotation and Clifford results, and checkable counterexamples to several broader readings. It does not establish unconditional solutions to BSD, Hodge, twin primes, or the Yang–Mills mass-gap problem.

The hinge gives a rotation law

For a real-linear J with J² = −I, the trigonometric action has angle addition, an identity, inverses, commutativity, and 2π periodicity.

Boundary: the algebraic law alone does not identify a Euclidean rotation.

Clifford actions supply hinges

With the negative-definite convention, unit vectors and orthogonal unit pairs square to −1. Their actions on a supplied module give hinges; the pair action is the quarter turn.

Boundary: a compatible inner product on that module is an additional ingredient.

A hinge can change Euclidean length

J(x,y) = (−2y, x/2) satisfies J² = −I. Yet it sends (1,0) to (0,1/2), reducing its Euclidean squared length from 1 to 1/4.

Repair: require metric compatibility. Under that hypothesis, the package proves inner-product and norm preservation.

04 / A six-step reading tutorial

Learn to read the guarantee.

No Lean experience required. Follow an example from a definition to a theorem, then inspect the assumptions and reproduce the checks.

Your route through the audit
Step 01 / Statements

A theorem is a precise contract.

Begin with the theorem’s type, then inspect each definition and hypothesis it mentions. Lean checks the implication you wrote. Whether it captures the intended geometry or arithmetic is another question to investigate.

Read this shape: “Given a hinge h and a proof that J preserves the inner product, R(θ) preserves the inner product.” The metric premise is part of the result, not a detail that can be dropped.

A structure field can also carry a proposition together with a proof supplied by the caller. Using that field is valid. The remaining question is where the caller obtains it for the actual object under discussion.

Open rotate_inner and look for hJ. It is the explicit metric hypothesis.

Step 02 / Algebra

Square to −I, then add angles.

A hinge is a real-linear operator J with J² = −I. Define R(θ) = cos(θ) I + sin(θ) J. Multiplying two such expressions and replacing J² by −I gives the usual angle-addition identities.

R(α)R(β)
= (cos α cos β − sin α sin β)I
+ (cos α sin β + sin α cos β)J
= R(α + β).

At θ = 0 you get I; at π/2 you get J; at π you get −I; at 2π you return to I. These are algebraic facts. A Clifford action is one source of such a J, using the stated sign convention and supplied module.

Read rotate_add and cliffordPlane_quarter_turn.

Step 03 / Geometry

Ask: a circle in which metric?

The orbit formula uses coefficients a and b with a² + b² = 1. Mapping that coefficient circle to a v + b Jv does not guarantee a Euclidean circle: the two spanning vectors may have different lengths or fail to be perpendicular.

Try this: in the rotation lab, choose “Anisotropic” and then 90°. The hinge relation still holds, while the Euclidean squared length becomes 0.250.

For J(x,y) = (−2y,x/2), the adapted squared length x² + 4y² stays constant. This illustrates why specifying the metric matters. The package proves Euclidean norm preservation when the corresponding compatibility hypothesis is present.

Compare orbit_eq_circle and norm_rotate with the counterexample.

Step 04 / Semantics

Keep the curve. Change a free input.

The BSD probe holds the supplied curve data fixed. One admissible analytic bundle uses L(s) = 1, with vanishing order 0; another uses L(s) = s − 1, with vanishing order 1. A supplied rank-zero group then produces opposite weak-rank verdicts.

What this establishes: the current interface permits analytic data that is not determined by its curve fields. It does not furnish a counterexample to the classical BSD conjecture, because these choices have not been identified with the curve’s actual Hasse–Weil L-function.

This method also detects the Hodge model’s freedom and the de Rham identity-map inhabitant. A useful next step is to constrain the interface with constructions and comparison theorems, then check that the unintended models are excluded.

Read weakRank_same_curve_opposite_verdicts.

Step 05 / Trust

Check the dependencies of the proof.

The compiled audit scans declarations by their defining module, so private names and names outside the public namespace are included. It rejects unsafe project declarations and axiom dependencies outside the allowed foundation.

propext · propositional extensionality
Classical.choice · classical choice
Quot.sound · quotient soundness

Five controls deliberately add a public axiom, private axiom, admitted proof, native proof certificate, or unsafe definition. Each must fail with the expected diagnostic. This tests the checker’s rejection behavior. It does not decide whether a mathematical model matches nature.

Inspect the axiom scanner and its controls.

Step 06 / Reproduction

Make the result inspectable by someone else.

Use the pinned Lean and Mathlib versions. Build both libraries, run the axiom audit, and check the controls and source manifest. Keep the workflow’s exact commit attached to any statement that a build passed.

Then choose a bounded mathematical obligation. For example, connect a supplied invariant to the actual arithmetic object, or replace a permissive geometric surrogate and prove its intended comparison.

The separate finite BSD follow-on takes this route: it proves an exact parity description of a 2,800-element image in a 5,600-element product of finite elliptic-curve groups. Its 52 named theorem declarations belong to a different Lean 4.28 package.
